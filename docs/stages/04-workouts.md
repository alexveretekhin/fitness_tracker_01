# Этап 4. Тренировки на сервере, подходы по одному

## Цель

Тренировка записывается так, как её делают в зале: сделал подход, нажал «+ подход», он сохранился на сервере. Дни, огоньки, история и аватар больше не живут в браузере.

## Что сделали

- **Подходы по одному.** Новая таблица `WorkoutSet` в [models.py](../../app/backend/app/models.py): одна строка = один подход (вес × повторы). Раньше у упражнения была одна запись «вес, подходы, повторы», и число повторов надо было знать заранее. Решение описано в [ADR 0005](../decisions/0005-one-row-per-set.md).
- **Миграция** [898a6f7857f1_one_row_per_set.py](../../app/backend/migrations/versions/898a6f7857f1_one_row_per_set.py). Она создаёт таблицу и переносит старые записи: «3 подхода по 15» превращаются в три подхода по 15.
- **API подходов** в [days.py](../../app/backend/app/api/days.py): добавить, исправить и удалить подход. Есть и `DELETE /api/days` для кнопки Reset data. Старый `PUT /days/{date}/exercises/{id}` удалён.
- **Карточка упражнения** [SetSheet.tsx](../../app/frontend/src/components/SetSheet.tsx):
  - список записанных подходов;
  - поля «Вес» и «Повторы» с кнопками − и + (вес шагом 2,5 кг);
  - кнопка «+ подход». Следующий подход сразу предлагается с теми же числами, обычно меняется только одно;
  - тап по подходу позволяет его исправить, × удаляет.
- **Всё из API:** главная, лента недели, история, выбор аватара и настройки берут данные с сервера ([src/api/index.ts](../../app/frontend/src/api/index.ts)). В браузере остались только выбранный день и счётчик на «+» ([useAppStore.ts](../../app/frontend/src/store/useAppStore.ts)).
- **Экран «Нет связи с сервером»** с кнопкой «Повторить», если бэкенд не запущен ([router.tsx](../../app/frontend/src/router.tsx)).
- **История:** дата в формате день.месяц и только упражнения, где есть подходы.
- **Тесты:** 14 штук в [test_api.py](../../app/backend/tests/test_api.py).

## Новые технологии

| Что | Простыми словами |
| --- | --- |
| Мутация (TanStack Query) | Запрос, который что-то меняет на сервере: добавить подход, удалить упражнение. Чтение называется query, изменение mutation |
| Инвалидация кэша | Пометка «эти данные устарели, перезагрузи». После нового подхода сводка дней перезагружается, и огонёк загорается |
| `setQueryData` | Положить ответ сервера прямо в кэш. Сервер после каждой правки присылает день целиком, поэтому экран обновляется без лишнего запроса |
| Миграция данных | Миграция, которая не только меняет таблицы, но и переносит в них старые записи |
| `ensureQueryData` | «Дай данные из кэша, а если их нет, загрузи». Так роутер проверяет аватар перед главной |

## Как запустить и проверить

После `git pull` **обязательно примени миграцию**, иначе бэкенд упадёт с ошибкой про колонки:

```powershell
cd D:\fitness_tracker_01\fitness_tracker
git checkout main
git pull
cd app\backend
uv sync
uv run alembic upgrade head
uv run fastapi dev
```

Во втором окне:

```powershell
cd D:\fitness_tracker_01\fitness_tracker\app\frontend
pnpm install
pnpm dev
```

Проверь: главная → тапни упражнение → поставь вес → «+ подход» → поменяй повторы кнопкой − → «+ подход» ещё раз. Закрой карточку и обнови страницу (F5): подходы на месте, потому что они на сервере.

Тесты: `cd app\backend; uv run pytest`.

## На что обратить внимание

- **Упражнения из этапа 3 не перенеслись.** Тогда они лежали в localStorage браузера, а сервер о них не знал. Аватар тоже нужно выбрать заново.
- **Миграция одна на всех.** Если на другом компьютере база старая, `alembic upgrade head` переведёт её на новые подходы, ничего не потеряв.
- **Reset data теперь удаляет тренировки на сервере**, отменить это нельзя.
- **`pnpm api` после изменения API.** В этом этапе API поменялся, поэтому клиент в `src/api/generated` перегенерирован.
- **Повторы от 1, вес от 0.** Вес 0 значит «свой вес», такой подход показывается как «15 повт.».
