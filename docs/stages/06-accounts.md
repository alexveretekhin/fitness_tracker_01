# Этап 6. Аккаунты и профиль

## Цель

У каждого человека свой аккаунт по почте и паролю, свои тренировки, XP и аватар. В профиле видно имя, почту, уровень, и оттуда можно выйти.

## Что сделали

- **Решения (ты выбрал 2026-11-13, [ADR 0014](../decisions/0014-accounts-email-jwt.md)):**
  - вход по почте и паролю, вход через Google добавим позже отдельным PR;
  - старые тренировки в новый аккаунт **не переносим**: новый аккаунт начинает с нуля. Старый «пользователь по умолчанию» остаётся в базе без почты, войти в него нельзя.
- **Бэкенд:**
  - у таблицы `user` новые поля: `email`, `password_hash`, `created_at` ([models.py](../../app/backend/app/models.py)), миграция `20155ba6bd0c`;
  - [security.py](../../app/backend/app/security.py): хеш пароля (Argon2) и токен входа (JWT);
  - [api/auth.py](../../app/backend/app/api/auth.py): `POST /api/auth/register` (почта, пароль от 8 символов) и `POST /api/auth/login`, оба отвечают токеном;
  - [deps.py](../../app/backend/app/deps.py): `CurrentUser` теперь берётся из токена. Нет токена или он плохой — ответ 401. Все адреса тренировок, XP и графиков сразу стали «личными», их код менять не пришлось;
  - каталог упражнений открыт всем, без входа;
  - `/api/me` теперь отдаёт и `email`;
  - seed больше не создаёт пользователя по умолчанию;
  - 10 новых тестов в [test_auth.py](../../app/backend/tests/test_auth.py), в том числе «второй пользователь не видит тренировки первого». Остальные тесты ходят под зарегистрированным пользователем (фикстура `client` в [conftest.py](../../app/backend/tests/conftest.py)).
- **Фронтенд:**
  - экран [Login.tsx](../../app/frontend/src/screens/Login.tsx) `/login`: переключатель «Вход / Регистрация», почта, пароль, ошибка под формой по-русски;
  - [lib/auth.ts](../../app/frontend/src/lib/auth.ts): хранит токен в localStorage;
  - [api/index.ts](../../app/frontend/src/api/index.ts): клиент сам прикладывает токен к запросам; на ответ 401 забывает токен и открывает вход; при входе и выходе кэш прошлого пользователя очищается;
  - [router.tsx](../../app/frontend/src/router.tsx): без входа все экраны, кроме заставки, ведут на `/login`. После регистрации сразу выбор аватара;
  - профиль `/me`: имя и почта под аватаром, внизу «Выйти»;
  - Настройки: в строке аккаунта имя и почта, внизу пункт «Выйти».

Скриншоты: `accounts/` в файлах проекта.

## Новые технологии

- **Хеш пароля (Argon2, библиотека `pwdlib`).** Пароль не хранится в базе. Хранится «отпечаток», из которого пароль не восстановить. При входе считаем отпечаток введённого пароля и сравниваем.
- **JWT (библиотека `pyjwt`).** После входа сервер выдаёт строку-токен: внутри id пользователя и срок годности (30 дней), всё подписано секретом `JWT_SECRET`. Фронтенд шлёт её в заголовке `Authorization: Bearer ...`. Подделать подпись без секрета нельзя.
- **OAuth2 Password flow.** Стандартный способ входа по логину и паролю. FastAPI его понимает, поэтому в `/docs` появилась кнопка **Authorize**: вводишь почту и пароль и пробуешь любые адреса прямо из браузера.

## Как запустить и проверить

После `git pull` поставь новые библиотеки и обнови базу:

```powershell
cd D:\fitness_tracker_01\fitness_tracker\app\backend
uv sync
uv run alembic upgrade head
uv run fastapi dev
```

Во втором окне:

```powershell
cd D:\fitness_tracker_01\fitness_tracker\app\frontend
pnpm dev
```

1. Открой http://localhost:5173: после заставки откроется экран входа.
2. «Регистрация» → почта и пароль от 8 символов → выбор аватара → главная, всё пусто.
3. Настройки: в строке аккаунта твоё имя (часть почты до @) и почта. Внизу «Выйти».
4. Выйди и войди снова: тренировки на месте. Попробуй неверный пароль: «Неверная почта или пароль».
5. Зарегистрируй вторую почту: у неё свои пустые тренировки.
6. http://127.0.0.1:8000/docs → **Authorize** → почта в поле `username`, пароль → можно звать любые адреса.

Тесты: `uv run pytest` в бэкенде, `pnpm test` во фронтенде.

## На что обратить внимание

- **Старые тренировки пропадут из вида.** Так ты решил: они лежат в базе у пользователя без почты, но войти в него нельзя. Если передумаешь, их можно перенести одной миграцией.
- **Секрет `JWT_SECRET`.** Для разработки работает значение по умолчанию. На настоящем сервере (этап 8) обязательно задай свой в `app\backend\.env`, иначе кто угодно сможет подделать токен:
  ```powershell
  uv run python -c "import secrets; print(secrets.token_urlsafe(32))"
  ```
  Если секрет поменять, все войдут заново.
- **Забыл пароль.** Восстановления пока нет (для него нужна отправка писем). Это задача на потом.
- **Токен в localStorage.** Просто и надёжно для нашего случая. Минус: если на сайт попадёт чужой скрипт, он сможет прочитать токен. Поэтому не вставляем на страницы чужой код.
- **Телефон.** Вход на телефоне отдельный: зарегистрируйся или войди там той же почтой.
