## Новые технологии

| Инструмент | Что это | Зачем нам |
| --- | --- | --- |
| Git | Система контроля версий: хранит историю всех изменений | Можно откатиться, посмотреть, кто что менял, работать в ветках |
| GitHub | Сайт, где лежит копия репозитория | Pull Request на каждый этап, резервная копия |
| uv | Менеджер пакетов и версий Python | Сам ставит нужный Python, создаёт `.venv` и ставит библиотеки. Заменяет `python -m venv` + `pip` |
| Node.js | Среда, которая запускает JavaScript вне браузера | Нужна для сборки фронтенда |
| pnpm | Менеджер пакетов для JavaScript | Быстрее и экономнее, чем стандартный npm |

## Как проверить

Открой новый PowerShell и выполни:

```powershell
git --version
uv --version
node --version   # должно начинаться с v22
pnpm --version
```

Подтянуть изменения этапа на компьютер:

```powershell
cd D:\fitness_tracker_01\fitness_tracker
git checkout main
git pull
```

## На что обратить внимание

- **Старый `.venv`.** Ты создавал окружение через `python -m venv`. Оно больше не нужно: на этапе 2 uv создаст своё в `app/backend/.venv`. Старую папку `.venv` в корне можно удалить.
- **Файлы Blender не кладём в git.** `.blend` по 80 МБ GitHub примет с трудом (лимит 100 МБ на файл), а репозиторий быстро станет огромным. Исходники держим вне репозитория (как сейчас в `Context_for_Cloude`), а в `art/` и потом в `app/frontend/public` кладём только готовые экспорты (WebP, WebM, GLB).
- **Вложенный репозиторий.** В `Context_for_Cloude/Assets` есть своя папка `.git`. Это отдельный репозиторий, он не связан с проектом. Не перемещай `Assets` внутрь `fitness_tracker`, иначе git запутается.
- **Новое окно терминала.** После установки программ PATH обновляется только в новых окнах PowerShell и VS Code.
- **Ветки.** В `main` напрямую не коммитим: для каждого этапа своя ветка и Pull Request.
