# 0003. Модель данных тренировок

- Дата: 2026-10-24
- Статус: принято

## Контекст

По концепту пользователь выбирает упражнения в день, а потом в карточке записывает вес, подходы и повторы. Огонёк дня горит, если тренировка была. Позже 3D-аватар будет по мышце показывать упражнения.

## Решение

- **Упражнение ↔ мышцы: многие ко многим** с ролью `primary`/`secondary`. Список группы показывает только упражнения, где она основная.
- **Коды мышц и упражнений строками** (`chest`, `barbell-bench`), а не числами. Их же получат объекты на 3D-модели в Blender.
- **День = `WorkoutDay`** (пользователь + календарная дата), в нём `DayExercise` с одной записью «вес × подходы × повторы» на упражнение, как в карточке из концепта.
- **Дата дня приходит от клиента**, сервер не вычисляет её из времени.
- **Огонёк = есть хотя бы одно упражнение с записанными подходами.**
- **Один пользователь по умолчанию** до этапа 6.

## Альтернативы

- **Отдельная запись на каждый подход** (подход 1: 60×10, подход 2: 65×8). Точнее, но концепт про одну карточку. Перейдём, если понадобится, это новая таблица и миграция.
- **Дата из времени сервера в UTC.** Тренировка поздно вечером уезжала бы на следующий день.

## Последствия

- Фронтенду нужно всегда отправлять дату в формате `YYYY-MM-DD`.
- Каталог живёт в `catalog.py` и обновляется командой seed. Позже можно сделать админку.
