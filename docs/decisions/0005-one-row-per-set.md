# 0005. Одна запись на каждый подход

- Дата: 2026-10-29
- Статус: принято, заменяет пункт про `DayExercise` в [ADR 0003](0003-data-model.md)

## Контекст

На этапе 3 карточка упражнения сразу просила вес, число подходов и повторы. Пользователь заметил, что в зале это заранее неизвестно: делаешь подход, потом решаешь, будет ли следующий и сколько в нём повторов. К тому же вес и повторы от подхода к подходу меняются.

## Решение

- **Таблица `WorkoutSet`**: одна строка = один подход (`weight`, `reps`, `position`). Число подходов не хранится, это просто количество строк.
- **Карточка добавляет подходы по одному** кнопкой «+ подход». Поля заранее заполнены значениями прошлого подхода.
- **Огонёк горит**, если в дне есть хотя бы один подход.
- **Каждая правка возвращает день целиком** (`DayOut`), чтобы фронтенд сразу обновил экран.
- **Миграция переносит старые записи**: «3 × 15» превращается в три подхода по 15. Обратная миграция собирает их обратно по первому подходу.

## Альтернативы

- **Оставить одну запись, но разрешить пустые поля.** Проще, но разный вес в подходах так не записать.
- **Хранить подходы списком в JSON-колонке.** Меньше таблиц, но по такому полю трудно считать статистику (рекорды, объём), а она понадобится на этапе 5.

## Последствия

- API подходов: `POST/PUT/DELETE /api/days/{date}/exercises/{exercise_id}/sets[/{set_id}]`.
- Сводка дней (`GET /api/days`) отдаёт `done_exercises`, названия упражнений с подходами. Это нужно истории.
- На этапе 5 рекорды и объём тренировки (вес × повторы) удобно считать прямо по `WorkoutSet`.
