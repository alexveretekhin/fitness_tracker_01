# 0017. Конвейер демо упражнений из Blender

- Дата: 2026-11-13
- Статус: принято

## Контекст

Нужно около 40–60 коротких зацикленных демо техники. Анимации автор делает сам в Blender, в стиле dark fantasy с toon-материалами. Рендерить каждое вручную (поменять анимацию, выставить кадры, нажать Render, перегнать в MP4) долго, легко ошибиться в имени файла или размере. Демо должны быть одинаковыми по кадру и лёгкими для телефона (ADR 0002: MP4/WebM, не GIF, до 500 КБ).

## Решение

- **Одна сцена на все демо:** один персонаж с ригом, общая камера, свет и фон. Упражнение = отдельный **Action**, названный ровно как id упражнения из `app/backend/app/catalog.py` (`push-ups`, `barbell-bench`).
- **Снаряды** лежат в коллекциях `props:<id>,<id>` (например `props:barbell-bench,dumbbell-bench`). Скрипт показывает такую коллекцию только в перечисленных демо.
- **Скрипт** [`art/blender/render_demos.py`](../../art/blender/render_demos.py) запускается Blender'ом в фоне (`--background`), по очереди ставит каждый Action на риг, рендерит кадры в PNG и через **ffmpeg** собирает `<id>.mp4` (H.264) и `<id>.webm` (VP9), 512×512, 24 кадра/с. Обёртка для PowerShell: `art/blender/render-demos.ps1`.
- **Последний кадр Action выкидываем:** он должен совпадать с первым, чтобы петля шла без рывка.
- **Подключение по имени файла:** готовые файлы кладутся в `app/frontend/public/animations/exercises/`, компонент `ExerciseDemo` сам ищет `<id>.webm`, затем `<id>.mp4`. Нет файла — заглушка «анимация скоро». Бэкенд и базу трогать не нужно; поле `demo` в каталоге остаётся только для особых путей.
- **Исходник `.blend` в git не кладём** (правило проекта, файлы по 80 МБ). Храним рядом с репозиторием, например `D:\fitness_tracker_01\demos.blend`. Git LFS можно подключить позже, если понадобится история версий сцены.

## Альтернативы

- **Отдельный .blend на каждое упражнение.** Камера и свет быстро разъедутся, менять стиль придётся в 60 файлах.
- **Рендер видео прямо из Blender (FFmpeg Video в Output).** Не нужен отдельный ffmpeg, но меньше контроля: нет `faststart` для быстрого старта в браузере, сложнее сделать два формата за один проход.
- **Список демо в базе (поле `demo` у каждого упражнения).** После каждого рендера пришлось бы править `catalog.py` и делать seed. Правило «имя файла = id» проще.
- **Прозрачный фон (WebM с альфа-каналом).** Safari на iPhone поддерживает его плохо, а MP4 прозрачность не умеет. Фон сцены делаем цветом приложения.
- **Анимированный WebP.** Весит в 5–6 раз больше MP4 (push-ups: 453 КБ против 72 КБ).

## Последствия

- Новое демо = новый Action с правильным именем + запуск скрипта. Код приложения менять не нужно.
- На компьютере нужен ffmpeg (`winget install Gyan.FFmpeg`).
- Опечатка в имени Action = демо не появится. Скрипт с `-List` показывает, какие Action ни к чему не подошли.
- Готовые MP4/WebM лежат в git: 60 демо × ~300 КБ ≈ 20 МБ, это нормально. Если вырастет сильно, перенесём на хостинг файлов на этапе 8.
- Скрипт проверен на кодировании и разборе каталога; сам рендер нужно проверить в Blender автора (версии 4.x и 5.x отличаются API, в скрипте есть проверки на оба).
