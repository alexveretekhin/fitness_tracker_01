# 0004. Как фронтенд общается с бэкендом

- Дата: 2026-10-24
- Статус: принято

## Контекст

Фронтенду нужны данные из API этапа 2. Писать запросы и типы руками долго, и они расходятся с бэкендом при каждой правке. Ещё фронтенд (порт 5173) и бэкенд (порт 8000) живут на разных адресах.

## Решение

- **Клиент генерируется из схемы OpenAPI** через `@hey-api/openapi-ts` с плагином TanStack Query. Схема сохраняется в `app/frontend/openapi.json` скриптом бэкенда, генерация одной командой `pnpm api`. Сгенерированный код лежит в git, чтобы сборка не требовала запущенного бэкенда.
- **Имя операции = имя функции в Python** (`get_day`, `list_muscle_groups`), чтобы функции клиента читались.
- **Прокси Vite**: фронтенд ходит на относительный адрес `/api`, Vite в разработке пересылает его на `127.0.0.1:8000`.
- **Данные сервера в TanStack Query, состояние интерфейса в Zustand** (выбранный день, счётчик на «+»).
- **На этапе 3 из API читается только каталог.** Дни и подходы пока в localStorage, переезд на API на этапе 4.

## Альтернативы

- **Писать fetch и типы руками.** Проще на старте, но каждая правка API = ручная правка фронта.
- **Генерация на лету из запущенного бэкенда** (`input: http://127.0.0.1:8000/openapi.json`). Тогда без бэкенда не соберёшь фронт, и CI сложнее.
- **CORS вместо прокси.** Работает (бэкенд его уже разрешает), но с телефона по адресу Wi-Fi пришлось бы добавлять каждый адрес в настройки.

## Последствия

- После правки API надо выполнить `pnpm api` и закоммитить изменения `openapi.json` и `src/api/generated`.
- При деплое (этап 8) фронт и API окажутся за одним адресом, и прокси заменит настройка сервера.
