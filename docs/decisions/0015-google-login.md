# 0015. Вход через Google (Google Identity Services)

- Дата: 2026-11-13
- Статус: принято

## Контекст

Автор хочет вход «как в топовых приложениях»: нажал на Google и вошёл, без ввода почты. Вход по почте и паролю уже есть (ADR 0014), токен у нас свой JWT.

## Решение

- На фронтенде кнопка Google Identity Services (скрипт `accounts.google.com/gsi/client`). Она отдаёт ID token Google.
- Бэкенд проверяет ID token библиотекой `google-auth` (подпись Google, срок, `aud` = наш `GOOGLE_CLIENT_ID`, `email_verified`) и выдаёт наш обычный JWT. Дальше всё как при входе паролем.
- Аккаунт ищем по почте. Нет — создаём без пароля. Есть — входим в него (почту подтвердил Google).
- `GOOGLE_CLIENT_ID` в `.env`. Пусто — кнопки нет (`GET /api/auth/config`), `/api/auth/google` отвечает 503.

## Альтернативы

- **Классический OAuth с переадресацией (Authorization Code flow).** Нужен Client Secret на сервере и страница возврата. Больше кода, а пользы для нас нет: токен Google нам нужен только один раз, чтобы узнать почту.
- **Готовые сервисы (Firebase Auth, Auth0, Clerk).** Быстро, но чужой сервис хранит пользователей, и придётся переделывать уже готовый вход.
- **Только подсказка браузера (`autocomplete=email`).** Уже работает, но это не настоящий вход в один тап.

## Последствия

- Нужен Client ID из Google Cloud Console, инструкция в `docs/stages/06-1-google-login.md`.
- Google не пускает адреса локальной сети (`192.168.x.x`): на телефоне кнопка заработает после деплоя на домен (этап 8).
- Пока приложение Google в режиме тестирования, войти через Google могут только добавленные Test users.
- Аккаунт из Google без пароля. Добавить пароль к нему пока нельзя.
